Context • Motivation

The Relative Grading Challenge

σ
Dynamic Class Distribution
Unlike schools with fixed grade cutoffs (e.g., >90 is S), VIT assigns grades based on standard deviation and class average. Boundaries shift with every batch.
%
Multi-Tier Weightage Scaling
5 separate evaluations: CAT-1 (15%), CAT-2 (15%), Quiz (15%), Digital Assessment (15%), and FAT (40%). Manual student conversions cause high error rates.
≪≫
Lack of Class Simulators
Existing apps only calculate past single-student GPA. There was no tool for professors or class reps to simulate entire batch cutoffs in real-time.
Engineering Architecture

Full-Stack Data Pipeline

1. Dynamic Client Grid
HTML5 • Vanilla JS • Bootstrap 5
Accepts parameters $N$ (Students) and $A$ (Subjects). Injects responsive form containers without reloading the browser. Validates input bounds (0-50, 0-100).
2. Flask Controller
Python 3.10+ • Jinja2
Extracts multi-nested POST payload. Normalizes and scales each raw exam component into a clean 100-mark unified metric per subject.
3. Statistical Engine
Relative Grading • In-Memory
Calculates Class Mean ($\mu$) and Standard Deviation ($\sigma$). Automatically maps relative letter grades and weighted credit CGPAs.

Grading Engine

Credit-Weighted CGPA Formulation

1. Course Credit Multiplier
Each subject $j$ carries designated credits $C_j$ (e.g., 4 credits for Core CSE, 3 credits for Theory). Grade Points $GP_j$ are multiplied:

Weighted_GP = GP_j × C_j
2. Student CGPA
The cumulative sum of weighted grade points is divided by the total registered credits:

CGPA = Σ(GP_j × C_j) / ΣC_j

Rounded to 2 decimal places for academic reporting.
3. Zero-SD Fail-Safe
If all students receive identical marks, Standard Deviation becomes 0:

Automatic Graceful Fallback: System immediately transitions to absolute thresholds (≥90=S, ≥80=A) to prevent division by zero errors.
